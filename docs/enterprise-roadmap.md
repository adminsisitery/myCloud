# MyCloud 企业级改造路线图

> 目标：把一个「能编译、但环境跑不起来、零测试、零 CI/CD」的微服务项目，改造成可长期维护、可持续演进的企业级项目。
>
> 原则：每阶段有明确验收标准，验收通过才进入下一阶段；不做没有验收标准的「伪完成」。

## 0. 现状基线（2026-11-04 核查）

| 维度 | 状态 |
|---|---|
| 架构 | 12 模块微服务，376 个 Java 文件，单体已退场 |
| 编译 | ✅ `mvn -DskipTests package` 可出 jar |
| 环境运行 | ❌ 仅编译级验证，未整体跑通 |
| 部署编排 | ❌ 无 Dockerfile / compose（旧单体编排已随单体退场） |
| 数据库迁移 | ❌ 靠手工建表，无版本化迁移 |
| 测试 | ❌ 0 个，且未引入任何测试依赖 |
| CI/CD | ❌ 无 |
| Maven Wrapper | ❌ `.mvn/wrapper` 缺失，CI 需先解决 Maven 版本 |
| 可观测 / 安全 / 文档 | ❌ 未做 |

## 阶段总览（依赖关系）

```
P0 可运行基线 ──→ P1 功能正确性 ──→ P2 测试体系 ──→ P3 CI/CD ──→ P4 企业级配套
```

并行说明：

- **P2 纯单元测试**不依赖环境，可与 P0 并行。
- **P3 的「编译 + 单测」**部分可提前搭建；「镜像构建 / 部署」依赖 P0 + P1。

## P0 可运行基线

> 目标：环境能一键起、12 服务能启动、核心链路能手动跑通。这是后续一切的前提。

| # | 事项 | 产出 | 验收标准 |
|---|---|---|---|
| 0.1 | Nacos 配置包重建 | `nacos-config/` 18 个 dataId + 导入脚本 | 实际导入 Nacos 后可见 18 条 dataId；服务启动无配置缺失报错 |
| 0.2 | 基础设施编排 | docker-compose（MySQL 8 / Redis 7 / RabbitMQ 3.13 / ES 8.11 / pgvector pg16 / Nacos 2.x），带数据卷 + 健康检查 | `docker compose up` 后各容器 healthy，数据可持久化 |
| 0.3 | 服务镜像 + 编排 | 12 个 Dockerfile（统一模板 + 参数）+ 按依赖顺序编排 | 一键 `docker compose up` 后 12 服务全启动，网关可访问 |
| 0.4 | 数据库迁移 | Flyway/Liquibase + 初始化 SQL（所有表 / PG vector / ES mapping） | 空库执行迁移后 schema 完整；重复执行无副作用 |
| 0.5 | `.env.example` 重写 | 按 Nacos 占位符整理的 `.env`，标注启动顺序 | 按示例填值即可启动，无缺失变量 |
| 0.6 | 全链路冒烟 | 冒烟清单 + 执行记录 | 登录 → 上传（普通/秒传/分片/直传）→ 管理/回收站 → 下载+Range → 文件夹 ZIP+异步打包 → 分享 → 搜索（MySQL+ES）→ 预览 → WebSocket → 6 定时任务 → AI 对话 全部通过 |

## P1 功能与正确性收尾

> 目标：消除已知运行时缺陷与服务间安全隐患。

| # | 事项 | 验收标准 |
|---|---|---|
| 1.1 | Feign 返回类型适配 | `/internal/**` 调用运行时无反序列化失败 |
| 1.2 | `/internal/**` 服务间鉴权 | 未携带合法内部凭证的请求被拒 |
| 1.3 | 异步事件补齐 | ai-service 写 `t_file_info` 后 ES/PG/操作日志落库；share-service 分享创建/取消落操作日志 |
| 1.4 | RPC 规范化 | Feign 具备超时/重试/熔断 + trace 透传，服务名走 `lb://` |
| 1.5 | MQ 可靠性 | 幂等（唯一索引 + 先落库去重）+ DLQ 重投 |
| 1.6 | 死代码清理 | 移除 `DirectUploadServiceImpl.cleanupExpired()`、重复工具类、IDE 残留引用 |

## P2 测试体系

> 目标：核心链路有自动化测试，有覆盖率基线。**此阶段可与 P0 并行启动。**

| # | 事项 | 验收标准 |
|---|---|---|
| 2.1 | 测试依赖引入 | 各模块引入 `spring-boot-starter-test` + JUnit5 + AssertJ/Mockito；根 pom 统一版本管理 |
| 2.2 | 单元测试 | 核心业务（上传/秒传/分享/权限/配额）覆盖关键分支 |
| 2.3 | 集成测试 | Testcontainers 覆盖上传/下载/分享/搜索核心链路 |
| 2.4 | 覆盖率门禁 | JaCoCo 出报告，设定行覆盖率基线（如 60%），不达标即失败 |

## P3 CI/CD

> 目标：push 即触发，编译 + 测试 + 镜像 + 部署全自动；质量不达标不进主干。

| # | 事项 | 验收标准 |
|---|---|---|
| 3.1 | Maven Wrapper 补全 | 仓库自带 `mvnw`，CI 不依赖本机 Maven 版本 |
| 3.2 | CI 骨架 | PR 触发 `mvn verify`（编译 + 单测 + 覆盖率） |
| 3.3 | 集成测试进 CI | CI 内跑 Testcontainers 集成测试 |
| 3.4 | 镜像构建 + 推送 | 编译通过后构建 12 镜像并推送镜像仓库 |
| 3.5 | 部署流水线 | 自动部署 dev/staging，生产需人工审批 |
| 3.6 | 质量门禁 | 编译 / 单测 / 集成 / 覆盖率 / 静态扫描（SpotBugs/PMD/Sonar）任一失败即阻断合并 |

## 关键决策点（需拍板）

| 决策 | 选项 | 推荐 |
|---|---|---|
| CI 平台 | GitHub Actions / GitLab CI / Jenkins | GitHub Actions（若仓库托管在 GitHub） |
| 数据库迁移工具 | Flyway / Liquibase | Flyway |
| 测试技术栈 | JUnit5 + Mockito + AssertJ + Testcontainers | 该组合（Spring 生态标准） |
| 镜像仓库 | Docker Hub / GHCR / 私有仓库 | GHCR（与 GitHub Actions 集成最顺） |
